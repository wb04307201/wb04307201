## 本模块规则

### 评估维度（追加 G 维度后）

| # | 维度 | 2 分 | 1 分 | 0 分 |
|---|------|------|------|------|
| B1 | 工具链完整度 | 有完整 Pipeline + 触发条件 | 有提及无链路 | 无 |
| B2 | 配置即代码 | 有完整 yaml + 注释 | 有片段无注释 | 无 |
| B3 | ❌/✅ 反例对比 | 有正反例（事故案例） | 只有正确用法 | 无对比 |
| B4 | 监控覆盖 | 有 SLI/SLO + 告警分级 | 有指标无分级 | 无 |
| B5 | 故障复盘 | 有 5Why + 改进项 + 时间线 | 有总结无深度 | 无 |

### 写作要求

- Pipeline 必须写清触发条件、阶段顺序、缓存、制品、审批和失败处理。
- YAML、脚本与 IaC 片段须可复制，并对关键字段、环境差异和敏感信息处理作说明。
- 监控文章须定义 SLI/SLO、指标、标签、告警分级、抑制规则和响应责任人。
- 工具选型至少有 ✅/❌ 场景对比，事故复盘采用时间线、影响、5Why 和改进项。
- 交付物要包含安全、权限、凭据、回滚、审计和成本意识等运维检查项。

### 子目录约定

- `01-tools/`：开发、构建、测试、版本控制、容器与常用工程工具。
- `02-workflow/`：CI/CD、发布、IaC、监控告警、运维流程与故障复盘。
