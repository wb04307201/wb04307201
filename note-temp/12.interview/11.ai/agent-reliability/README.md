# Agent 跑偏/绕路/死循环 — 工程解法

← 返回 [11.ai 面试题](../README.md)

> 引子：凌晨 3 点，Agent 调用 search 工具 50 次，任务未完成，账单 $80。怎么防？

## 一、核心陷阱（咬文嚼字）

| 陷阱 | 表面理解 | 真实原因 | 核心防护 |
|------|---------|---------|---------|
| **Prompt 模糊 → Agent 自由发挥** | Agent 不够聪明 | Prompt 缺"任务边界 + 禁止动作" | L1：系统 Prompt 强制边界 |
| **工具返回空 → 死循环重试** | 工具 bug | Agent 认为"搜索词不对" → 换词重试 | L2：Verifier 检测空结果 |
| **上下文溢出 → 重复已做步骤** | Agent 记忆力差 | context window 满了 → 早期步骤被截断 | L3：状态快照回滚 |
| **无 Verifier → 错误累积** | Agent 一次写不对 | 无每步检查 → 错误滚雪球 | L2：每步过 Verifier |
| **无成本熔断 → 烧 $100+** | Agent 效率低 | 无 token 上限 → 死循环烧钱 | L4：成本熔断 |

---

## 二、5 大陷阱详解

### 2.1 陷阱 1：Prompt 只说"完成任务" → Agent 自由发挥

**表面理解**：Agent 不够聪明，理解不了任务。

**真实原因**：Prompt 缺少"任务边界"和"禁止动作"。Agent 没有被约束范围，就用自己的判断。

```text
❌ 错误：
"请帮我完成这个任务。"

✅ 正确：
"任务：生成用户登录接口。
边界：只写 Java 代码，不修改数据库。
禁止：不创建新文件，不删除现有代码，不调用外部 API。"
```

**防护**：系统 Prompt 强制"做什么 / 不做什么"。

### 2.2 陷阱 2：工具返回空结果 → Agent 死循环重试

**表面理解**：工具出了 bug，或者网络问题。

**真实原因**：Agent 认为"搜索词不对" → 换词重试 → 仍然空 → 继续换词 → 无限循环。

```text
search("用户登录") → 空
  → Agent：换词
search("登录接口") → 空
  → Agent：再换
search("login API") → 空
  → Agent：再再换
search("authentication method") → 空
  → ... 50 次后，$80 账单
```

**防护**：L2 Verifier 检测"空结果" → 反馈"无匹配，请换策略"（不是换词重试）。

### 2.3 陷阱 3：上下文溢出 → Agent 重复做已完成的步骤

**表面理解**：Agent 记忆力差，记不住做过什么。

**真实原因**：context window 满了 → 早期步骤被截断 → Agent 看不到之前的进展 → 重复劳动。

**防护**：L3 状态快照回滚（每步保存状态，溢出后从快照恢复）。

### 2.4 陷阱 4：无 Verifier → 错误累积到最终输出

**表面理解**：Agent 一次写不对，质量差。

**真实原因**：没有每步检查机制，第一步的错误累积到第 10 步，最终输出错误百出。

**防护**：L2 Verifier 每步检查（语法 + 语义 + 业务规则）。

### 2.5 陷阱 5：无成本熔断 → 单次任务烧 $100+

**表面理解**：Agent 效率太低，浪费时间。

**真实原因**：没有 token 上限，Agent 死循环无限烧钱，账单失控。

**防护**：L4 成本熔断（50k tokens 上限 + 80% 告警 + 100% 强制停止）。

## 三、4 层工程防线（速查表）

| 防线 | 定位 | 核心机制 | 防什么 | 触发条件 |
|------|------|---------|--------|---------|
| **L1 Prompt 约束** | 第一道防线 | 系统 Prompt 强制"任务边界 + 禁止动作" | 目标漂移 | Agent 行动前 |
| **L2 Verifier 检测** | 每步检查 | 语法/语义/业务规则检查 + 空结果检测 | 工具误用、错误累积 | 每步输出后 |
| **L3 状态回滚** | 错误兜底 | 每步快照 + 连续失败 3 次回滚 | 状态丢失 | Verifier 连续失败 |
| **L4 成本熔断** | 最后一道 | token 上限 + 80% 告警 + 100% 熔断 | 成本失控 | token 达阈值 |

**交叉矩阵**：

| 失败模式 | 主要防线 | 辅助防线 |
|---------|---------|---------|
| 目标漂移 | L1 Prompt 约束 | L4 成本熔断 |
| 工具误用 | L2 Verifier 检测 | L3 状态回滚 |
| 状态丢失 | L3 状态回滚 | L2 Verifier 检测 |
| 错误累积 | L2 Verifier 检测 | L3 状态回滚 |
| 成本失控 | L4 成本熔断 | L1 Prompt 约束 |

## 四、反直觉点

| 反直觉点 | 表面理解 | 真实情况 |
|---------|---------|---------|
| **Agent 越强越需要约束** | 强 Agent 不需要太多约束 | 强 Agent 跑偏成本更高（跑得快 = 错得快） |
| **Verifier 不是查最终输出** | Verifier = 最终质量检查 | Verifier = 每步都查，早期拦截错误 |
| **状态回滚比让 Agent 自修更可靠** | Agent 应该能自己修 | Agent 已陷错误上下文，需干净状态重启 |
| **空结果不是 Agent 笨** | Agent 不够聪明 | 工具描述缺"空结果怎么办"的指令 |

## 五、面试话术（90 秒版）

> Agent 跑偏的 5 大根因是：
> 1. **Prompt 模糊** → Agent 自由发挥（缺任务边界）
> 2. **工具误用** → 参数错误或空结果死循环
> 3. **状态丢失** → context window 满了重复做已完成的步骤
> 4. **验证缺失** → 错误累积到最终输出
> 5. **成本失控** → 无熔断，单次任务烧 $100+
>
> 4 层防线各司其职：
> - **L1 Prompt 约束**：系统 Prompt 强制"做什么 / 不做什么"
> - **L2 Verifier 检测**：每步输出过 Verifier（语法/语义/空结果），失败最多重试 3 次
> - **L3 状态回滚**：连续失败 3 次 → 回滚到上一个成功快照
> - **L4 成本熔断**：token 上限（简单 10k / 中等 50k / 复杂 100k），80% 告警 + 100% 强制停止
>
> 最反直觉的一点：状态回滚比"让 Agent 自己修复"更可靠，因为 Agent 已经陷入了错误上下文，需要从干净状态重启。

## 六、生产案例：凌晨 3 点的 $80 账单

### 现象

凌晨 3 点告警：Agent 调用 search 工具 50 次，任务未完成，账单 $80。

### 根因定位

```text
search("用户登录") → 空
  → Agent 判断：搜索词不对 → 换词
search("登录接口") → 空
  → Agent 判断：还是不对 → 再换
search("login API") → 空
  → ... 50 次循环
```

**三大缺失**：
1. 工具描述没有"空结果时怎么办"的指令
2. 没有 Verifier 检测"空结果"状态
3. 没有成本熔断限制

### 防护方案（复盘后落地）

| 防线 | 落地动作 | 效果 |
|------|---------|------|
| L2 Verifier | 检测"空结果" → 反馈"无匹配，请换策略" | 不盲目换词重试 |
| L3 回滚 | 连续 3 次空结果 → 回滚到搜索前状态 | 避免越搜越偏 |
| L4 熔断 | 30 次搜索 / 20k tokens → 告警 + 强制总结 | 不会烧 $80+ |
